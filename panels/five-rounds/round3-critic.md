## Round2 malformed-SVG finding: independently resolved

Retargeted the exact two earlier counterexamples. `safePacketSvg` now rejects both multiple SVG document roots and the invalid `&#0;` XML character reference. The implementation requires one root and its SVG namespace and rejects forbidden XML characters. An actual generated source sketch still passes the stricter allowlist and independently parses in ElementTree. The old `javascript:` primary-source mutation also remains rejected by the current registry validator.

This lifts the concrete earlier export-fidelity blocker; it does not claim the restricted parser accepts every SVG feature or replaces a general XML sanitizer. The supported authored sketch subset remains deliberately narrow and renders in the HTML packet as an inert data image with restrictive CSP. No payload was executed.

## Real field explanations and human packet: passed within current scope

Queried actual imported R1/R2/R3 contract state-and-unit plus parameter sections. **60 distinct real source keys** have declared field explanations with no missing key in those two sections. This is not automatic all-equation-token or source-corpus understanding: equation prose, future keys and physical validation stay outside that coverage statement.

Inspected scoped term/equation output and asserted current/imaginary unit, peak/RMS and rank/nullity distinctions for the selected coupled record. Constructed a packet using the same portable JSON-normalized options path as Studio. Its readable HTML now includes the inert sketch, technical terms/equations, a human “What remains unknown” section, turns/ratings limits and source identity. Generated text remains escaped. The source record is not mutated or promoted from proposed to physically validated by export.

The strict packet layer correctly requires portable values; optional undefined fields in raw term objects are removed by Studio's existing serialization before packet creation. That caller boundary was respected in this probe. No claim is made that arbitrary unnormalized TypeScript objects are valid portable packets.

## New explicit draft store: independent adverse-input checks passed

Executed current `studio-drafts.ts` directly with an isolated in-memory storage implementation and the real coupled-coil record:

- Saved and read a geometry-only view state; the restored fields matched exactly.
- Changed the record's own source hash, geometry source hash, contract hash and asset hash independently. All four cases returned `source-conflict`, refused save-overwrite and preserved original stored bytes.
- Corrupt JSON returned `invalid`; another save refused to overwrite it. Only explicit delete removed that one record's draft.
- Denied storage returned `unavailable`; the passed state object remained unchanged and could still produce a geometry-only sketch with no electrical parameter recalculation.

The actual Studio only calls `change()` on a `ready` load result, never on a returned conflict draft. Save/load/delete are explicit controls and drafts are not autosaved. The feedback is keyed to the selected record ID, preventing an old record's status from appearing under a new selection. These are native/API and source-inspection findings, not a browser reload result.

## Limits for rounds4–5

- Round4 should observe the actual selected sketch and human guide, component inspection through keyboard/touch, units/scenario continuity and export readability. A native geometry or field-coverage assertion is not human usability validation.
- Draft/source agreement is a byte-identity gate, not proof that the source's proposed apparatus is correct, safe, built or measured. Draft failure leaves the current tab usable; it does not silently recreate source data.
- Annotation geometry remains independent of L/M/k, ratings, calibration and physical energy predictions. Unknowns remain unknown in the Studio and packet.
- The artwork and exact source drawing remain separate. A selected original drawing may be unavailable, while authored geometry can remain available; neither should be silently substituted for the other.
- No new room/energy suite was repeated merely to count panel activity. No Reddit collection, physical experiment, heritage measurement or human user test occurred in this review.

No consequential blocker remains in this round3 code snapshot. Final acceptance is deferred to actual changed artifacts in rounds4 and5.
